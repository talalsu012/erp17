المرحلة 1: الفحص (بدون تعديل)

قم بمراجعة شاملة (audit) لهذا المشروع Laravel دون تعديل أي ملف.
أريد تقريراً مرتباً حسب الخطورة (حرج / مهم / تحسين) يغطي:
1. الأمان: SQL injection، mass assignment، صلاحيات ناقصة، بيانات حساسة في الكود، CSRF، رفع الملفات
2. البنية: controllers ضخمة، منطق مكرر، منطق في الـ views، غياب Form Requests و Policies
3. قاعدة البيانات: N+1 queries، فهارس ناقصة، migrations غير متسقة، غياب transactions في العمليات المركّبة
4. الكود الميت والملفات غير المستخدمة
5. التسمية والاتساق
لكل مشكلة اذكر: الملف، السطر، لماذا هي مشكلة، والحل المقترح.
  المشروع على Laravel 13 و Filament 5. لا تستخدم صيغ Filament 3 أو 4 القديمة.
  عند الشك في أي API راجع التوثيق عبر Boost أو اقرأ الكود في vendor/filament قبل الكتابة.

المرحلة 3: أدوات الجودة الآلية
أضف وأعدّ الأدوات التالية:
- Laravel Pint لتنسيق الكود
- Larastan (PHPStan) بدءاً من level 5
- Rector لتحديث الكود للإصدار الحالي
شغّلها، وأصلح المخالفات على دفعات صغيرة، وشغّل الاختبارات بعد كل دفعة.
ثالثاً: اختبارات Filament

Filament:
1. Resources ضخمة: هل النموذج (form) والجدول (table) مفصولان في كلاسات Schemas و Tables مستقلة؟
2. منطق أعمال مكتوب داخل closures في ->action() أو mutateFormDataBeforeCreate أو afterCreate
3. الصلاحيات: هل لكل Resource Policy؟ هل توجد أزرار أو صفحات تظهر لمن لا يملك الصلاحية؟
4. أداء الجداول: N+1 في الأعمدة والعلاقات، غياب eager loading، أعمدة searchable/sortable بلا فهارس
5. التكرار بين Resources (حقول وفلاتر وأعمدة متكررة يمكن توحيدها)
6. الـ Widgets: استعلامات ثقيلة بلا cache
7. استخدام الصيغ القديمة أو المهجورة (deprecated) من إصدارات Filament السابقة

Laravel:
8. الأمان، العلاقات، الـ migrations، الـ transactions، الكود الميت

لكل مشكلة: الملف، السبب، الحل المقترح.



اكتب اختبارات Pest باستخدام أدوات اختبار Filament و Livewire لكل Resource مهم:
- صفحة القائمة تفتح وتعرض السجلات
- الإنشاء والتعديل ينجحان ببيانات صحيحة ويفشلان ببيانات خاطئة
- المستخدم بدون صلاحية لا يستطيع الوصول
- الـ Actions المهمة تعمل (مثلاً: اعتماد، إلغاء، تصدير)
الهدف تثبيت السلوك الحالي. شغّل الاختبارات وتأكد أنها تنجح.






المرحلة 4: إعادة الهيكلة (وحدة واحدة في كل جلسة)


خذ وحدة [الطلاب] فقط. قبل التعديل اعرض عليّ خطة، ثم بعد موافقتي نفّذ:
- انقل التحقق إلى Form Requests
- انقل الصلاحيات إلى Policies
- انقل المنطق من الـ Controller إلى Service أو Action classes
- استخدم Eloquent relationships و eager loading لإزالة N+1
- غلّف العمليات المركّبة بـ DB::transaction
- استبدل القيم الثابتة (الحالات، الأنواع) بـ PHP Enums
- استخدم API Resources إن كان هناك API
لا تغيّر سلوك النظام. شغّل الاختبارات بعد كل خطوة، واعرض ملخص التغييرات.
رابعاً: إعادة هيكلة Resource واحد في كل جلسة
خذ [StudentResource] فقط. اعرض الخطة أولاً وانتظر موافقتي، ثم:
- افصل النموذج في كلاس Schema والجدول في كلاس Table حسب بنية Filament 5
- انقل أي منطق أعمال من closures الـ Actions وصفحات Create/Edit إلى Action classes
  في app/Actions، واجعل Filament يستدعيها فقط
- غلّف العمليات المركّبة بـ DB::transaction
- أضف eager loading للعلاقات المعروضة في الجدول، وأضف الفهارس اللازمة بـ migration جديدة
- حوّل الحالات والأنواع إلى PHP Enums تطبّق HasLabel و HasColor و HasIcon
- استخرج الحقول والفلاتر المتكررة إلى مكوّنات قابلة لإعادة الاستخدام
- تأكد أن Policy مربوطة وتغطي كل العمليات
لا تغيّر السلوك. شغّل الاختبارات بعد كل خطوة.

- حوّل الاستيراد والتصدير إلى Importer و Exporter classes تعمل عبر queue

- أضف لـ GitHub Actions: Pint و Larastan والاختبارات
